\section{\underline{Introduction and Goal}}
% =============================================================================

The goal of this exercise is to build a complete machine learning pipeline
for a real-world medical classification problem: predicting the survival
outcome of patients diagnosed with liver cirrhosis.
The dataset originates from a Mayo Clinic clinical study conducted between
1974 and 1984~\cite{dickson1989}, published in the UCI Machine Learning
Repository.

The work covers the full ML project lifecycle:
\begin{itemize}
  \item \textbf{Data Mining} -- exploratory analysis of features and labels.
  \item \textbf{Data Preparation} -- train/validation/test split, missing
        value imputation, and preprocessing experiments (standardization,
        normalisation, PCA).
  \item \textbf{Classification} -- Naive Bayes and Decision Tree classifiers
        with systematic hyperparameter tuning.
  \item \textbf{Evaluation} -- comparison of all configurations using
        accuracy, precision, recall, and macro F1-score.
  \item \textbf{Bonus} -- Random Forest and cost-complexity pruning as an
        overfitting mitigation technique.
\end{itemize}

All experiments were implemented in Python using \code{scikit-learn}~\cite{sklearn}.
The dataset was accessed via the \code{statsmodels} R-dataset mirror of the
well-known \code{pbc} (Primary Biliary Cirrhosis) survival study dataset.

\section{\underline{Theoretical Background}}
% =============================================================================

The theoretical foundations are covered in the assignment sheet.  This section
briefly recaps the key concepts applied in the experiment.

\subsection{Supervised Classification}

Given a labelled dataset $\mathcal{D} = \{(\mathbf{x}_i, y_i)\}_{i=1}^N$
where $\mathbf{x}_i \in \mathbb{R}^d$ and $y_i \in \mathcal{Y}$, supervised
classification aims to learn a mapping $f : \mathbb{R}^d \to \mathcal{Y}$
that minimises misclassification on unseen data.

\subsection{Naive Bayes Classifier}

The Naive Bayes classifier applies Bayes' theorem under the \emph{conditional
independence assumption}:

\[
  P(y \mid \mathbf{x}) \;\propto\; P(y)\prod_{i=1}^{d} P(x_i \mid y).
\]

The \emph{Gaussian} variant (used here) models each $P(x_i \mid y)$ as a
Gaussian distribution $\mathcal{N}(\mu_{iy}, \sigma^2_{iy})$.  The
\emph{variance smoothing} hyperparameter $\varepsilon$ adds a fraction of
the largest feature variance to all per-feature variances, preventing
singular covariance and acting as a regulariser:

\[
  \hat{\sigma}^2_{iy} = \sigma^2_{iy} + \varepsilon \cdot \max_j \sigma^2_j.
\]

\subsection{Decision Tree (ID3 / C4.5 principle)}

A decision tree recursively partitions the feature space by choosing the
split that maximises \emph{Information Gain}:

\[
  G(A) = H(S) - \sum_{v \in \text{Values}(A)} \frac{|S_v|}{|S|}\,H(S_v),
\]

where $H(S) = -\sum_{x \in \mathcal{X}} p(x)\log_2 p(x)$ is the Shannon
entropy.  Deeper trees fit training data increasingly well but tend to
\textbf{overfit}: the gap between training and validation accuracy grows
with depth.

\subsection{Evaluation Metrics}

For a three-class problem the macro-averaged variants are used:

\[
  \text{ACC} = \frac{\text{TP}+\text{TN}}{N}, \qquad
  \text{Precision} = \frac{\text{TP}}{\text{TP}+\text{FP}}, \qquad
  \text{Recall} = \frac{\text{TP}}{\text{TP}+\text{FN}},
\]
\[
  F_1 = \frac{2\,\text{TP}}{2\,\text{TP}+\text{FP}+\text{FN}}.\]

\subsection{PCA}

Principal Component Analysis rotates the feature space so that the new axes
(principal components) are ordered by decreasing variance.  Retaining the
top $k$ components that explain 95\% of the total variance reduces
dimensionality while preserving most information.

\subsection{Cost-Complexity Pruning}

Post-hoc pruning controls overfitting by penalising tree complexity.  A
subtree $T_t$ is replaced by a leaf when its \emph{effective alpha}
$\alpha_{\text{eff}} = \frac{R(t) - R(T_t)}{|T_t|-1}$ falls below a tunable
threshold $\alpha_{\text{ccp}}$, where $R(\cdot)$ denotes the misclassification
cost.  Higher values of $\alpha_{\text{ccp}}$ produce smaller, more general trees.

\section{\underline{Task 2 -- Data Preparation}}
% =============================================================================

\subsection{Categorical Encoding}

Before modelling, categorical features were encoded as integers:

\begin{itemize}
  \item Binary features (\code{Sex}, \code{Ascites}, \code{Hepatomegaly},
        \code{Spiders}, \code{Drug}): mapped to 0/1.
  \item Ordinal feature \code{Edema}: N$\to$0, S$\to$1, Y$\to$2.
  \item Target \code{Status}: label-encoded alphabetically as
        C$\to$0, CL$\to$1, D$\to$2.
\end{itemize}

\subsection{Missing Value Imputation}

All missing values were imputed using the \textbf{median strategy} for
numerical features (robust to skewed distributions and outliers) and the
\textbf{most-frequent strategy} for categorical/binary features.  Imputation
statistics were computed on the training set and applied to validation and
test sets to avoid data leakage.

\begin{lstlisting}[style=python, caption={Missing value imputation with scikit-learn.}]
from sklearn.impute import SimpleImputer

num_imputer = SimpleImputer(strategy="median")
X_imputed_num = num_imputer.fit_transform(X_train[num_feats])
\end{lstlisting}

After imputation the dataset contained \textbf{zero} missing values.

\subsection{Data Splitting}

The 418 samples were split into three disjoint sets using stratified sampling
(to preserve class ratios):

\begin{center}
\begin{tabular}{lcc}
\toprule
\textbf{Set} & \textbf{Size} & \textbf{Proportion} \\
\midrule
Training   & 250 & 59.8\% \\
Validation & 84  & 20.1\% \\
Test       & 84  & 20.1\% \\
\bottomrule
\end{tabular}
\end{center}

Stratification ensures each split mirrors the full 55\%/39\%/6\% class ratio.
With only 25 \code{CL} samples, this ratio is critical to maintain.

\newpage
\subsection{Preprocessing Variants}

Four preprocessing pipelines were compared to study their effect on
classification:

\begin{enumerate}
  \item \textbf{None} -- raw imputed features (integer-encoded categoricals,
        numerical values at their original scale).
  \item \textbf{Standardization} -- zero mean, unit variance via
        \code{StandardScaler}.  Appropriate for Gaussian NB (removes scale
        bias in variance estimation) and distance-based methods.
  \item \textbf{Normalization} -- L2 row-normalization via
        \code{Normalizer}. Maps each sample to the unit sphere.
  \item \textbf{PCA} -- applied on top of standardized features; retains
        \textbf{15 principal components} that together explain
        $\geq 95\%$ of variance.
\end{enumerate}

Figure~\ref{fig:pca} shows the explained variance per component; the first
component alone accounts for about 18\% of total variance, while 15
components are needed to reach 95\%.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.58\textwidth]{figures/fig_pca.pdf}
  \caption{PCA explained variance. Dashed line at 95\%.  15 components
           are retained, reducing from 17 to 15 dimensions.}
  \label{fig:pca}
\end{figure}

\textbf{Impact on Naive Bayes:} Standardization significantly affects GNB
because the model assumes feature independence and uses per-feature variance
estimates.  Without standardization, highly variable features (Alk\_Phos,
std = 2140) dominate the likelihood computations.

\textbf{Impact on Decision Trees:} Decision trees are scale-invariant (they
use only rank-order of feature values for splits), so standardization and
normalization produce identical trees.  PCA, however, changes the feature
space and therefore changes the splits.

\subsection{Naive Bayes -- Hyperparameter Tuning}

The \code{GaussianNB} classifier has one principal hyperparameter:
\textbf{var\_smoothing} ($\varepsilon$), which controls the amount of
variance added to the Gaussian estimates.  Four values were tested across all
four preprocessing pipelines (Table~\ref{tab:nb_results}).

\begin{table}[H]
\centering

         Best F1 per preprocessing highlighted in bold.}
\label{tab:nb_results}
\small
\begin{tabular}{llcccc}
\toprule
\textbf{Variant} & \textbf{Preprocessing} &
\textbf{Train Acc} & \textbf{Val Acc} & \textbf{Val Prec} &
\textbf{Val F1} \\
\midrule
NB (default, $\varepsilon{=}10^{-9}$) & None          & 0.724 & 0.643 & 0.444 & 0.437 \\
NB ($\varepsilon{=}10^{-5}$)           & None          & 0.636 & 0.643 & 0.448 & 0.417 \\
NB ($\varepsilon{=}10^{-2}$)           & None          & 0.588 & 0.583 & 0.401 & 0.322 \\
\midrule
NB (default, $\varepsilon{=}10^{-9}$) & Standardized  & 0.428 & 0.345 & 0.484 & 0.351 \\
NB ($\varepsilon{=}10^{-5}$)           & Standardized  & 0.652 & 0.524 & 0.508 & 0.462 \\
\best{NB ($\varepsilon{=}10^{-2}$)}    & \best{Standardized} & \best{0.712} & \best{0.643} & \best{0.528} & \best{0.524} \\
\midrule
NB (default, $\varepsilon{=}10^{-9}$) & Normalized    & 0.688 & 0.560 & 0.492 & 0.472 \\

\midrule

NB ($\varepsilon{=}10^{-2}$)           & PCA           & 0.752 & 0.702 & 0.469 & 0.473 \\
\bottomrule
\end{tabular}
\end{table}

\textbf{Key observations:}
\begin{itemize}
  \item With \emph{no preprocessing}, the default $\varepsilon{=}10^{-9}$
        already achieves val\_acc = 0.643.  Increasing $\varepsilon$ to
        $10^{-2}$ hurts performance (over-smoothing).
  \item With \emph{standardization}, large $\varepsilon$ ($10^{-2}$) is
        needed because the standardized variances are near 1 and small
        smoothing causes near-zero variance for low-variance features,
        yielding degenerate likelihoods.  The best NB result overall is
        \textbf{val\_acc = 0.643, F1 = 0.524} (\code{NB-vs=1e-2},
        Standardized).
  \item With \emph{PCA}, the default smoothing works well (val\_acc = 0.714)
        because PCA components are orthogonal and of comparable scale,
        making variance estimation more uniform.
\end{itemize}

\textbf{Key observations:}
\begin{itemize}
  \item The unlimited-depth tree achieves perfect training accuracy (1.000)

  \item Depths beyond 5 consistently hurt generalisation on this dataset.
  \item PCA preprocessing improves DT substantially (F1: 0.616 vs.\ 0.503
        at depth=3), likely because PCA removes correlated features and
        creates a cleaner split structure.
\end{itemize}

\subsection{Bonus -- Random Forest}

Random Forest~\cite{breiman2001} builds an ensemble of decision trees, each
trained on a bootstrap sample with random feature subsets, and aggregates by
majority vote.  It inherently reduces variance compared to a single tree.

\subsection{Bonus -- Overfitting Mitigation via Cost-Complexity Pruning}

Post-hoc \emph{minimal cost-complexity pruning} was applied to the
unlimited decision tree (trained on standardized features).  The pruning
path yields a monotonically decreasing tree size as $\alpha_{\text{ccp}}$
increases.

        benefiting from its dominant presence (55\% of data).
  \item \textbf{Class D} is predicted substantially better by DT and RF
        (F1 = 0.71 and 0.75) than by NB (0.49).
\end{itemize}

         per preprocessing, for each classifier family).}
\label{tab:prep_impact}

\toprule
\textbf{Classifier} & \textbf{None} & \textbf{Standardized} & \textbf{Normalized} & \textbf{PCA} \\
\midrule
Naive Bayes   & 0.643 & \textbf{0.643} & 0.595 & 0.714 \\

\begin{itemize}
  \item For \textbf{Naive Bayes}, PCA achieves the best accuracy (0.714)
        but standardization achieves the best F1 (0.524), because PCA with
        default smoothing struggles to separate class D from C despite high
        accuracy.
  \item For \textbf{Decision Trees}, PCA is clearly the best preprocessing
        (+7.2 pp over None in accuracy, +11.3 pp in F1).  The
        decorrelation of features by PCA helps the tree find cleaner,
        more informative splits.
  \item Normalization (L2 row-wise) is generally the weakest preprocessing:
        it encodes information about the relative proportions of features
        within a sample rather than their absolute values, which is less
        meaningful for clinical tabular data.
\end{itemize}

\section{\underline{Conclusions}}
% =============================================================================

\subsection{Summary of Results}

All experiments confirmed that predicting survival outcome from the Mayo
Clinic PBC dataset is a moderately difficult 3-class problem, primarily
due to severe class imbalance in the \code{CL} category.

The main findings are:

\begin{enumerate}
  \item \textbf{PCA} is the most beneficial preprocessing step for both
        classifier families.  It removes multicollinearity among clinical
        measurements, reduces from 17 to 15 dimensions, and creates a
        feature space more amenable to splitting.

  \item \textbf{Decision Tree with depth=3 and PCA} is the best single
        classifier:  test accuracy 72.6\%, macro F1 = 0.578.  Shallow
        trees generalise much better than deep ones: the unlimited tree
        overfits perfectly (train acc = 1.000) while achieving only
        67.9\% on the validation set.

  \item \textbf{Naive Bayes} is inferior to DT on this dataset
        (test acc = 63.1\%, F1 = 0.470), likely because the conditional
        independence assumption is violated -- clinical biomarkers are
        strongly correlated (e.g.\ Bilirubin, Copper, and Stage all
        increase together with disease severity).

  \item \textbf{Random Forest} (bonus) achieves the best overall accuracy
        (test acc = 76.2\%) while suffering on \code{CL} recall due to
        the imbalance.

  \item \textbf{Cost-complexity pruning} (bonus) effectively reduces
        the train/val accuracy gap by 20+ percentage points, confirming
        its value as an overfitting countermeasure.
\end{enumerate}

\subsection{Limitations and Future Work}

\begin{itemize}
  \item The \code{CL} class (only 25 samples, $\sim$3 in training) is
        effectively unlearnable with standard algorithms.  Techniques
        such as SMOTE oversampling, class-weight balancing, or a
        two-stage classifier (first binary D vs.\ not-D, then CL vs.\ C)
        could address this.
  \item With only 418 samples, cross-validation (e.g.\ 5-fold) would
        give more robust hyperparameter estimates than a single 80/20
        split.
  \item Gradient Boosting (XGBoost, LightGBM) would likely outperform
        Random Forest on this tabular dataset.
\end{itemize}
