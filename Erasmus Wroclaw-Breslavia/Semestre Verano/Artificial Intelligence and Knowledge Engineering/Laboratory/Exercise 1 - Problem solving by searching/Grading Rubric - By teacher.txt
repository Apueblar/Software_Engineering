Grading Rubric — Assignment 1 (AI&KE)
Total: 100 points (code) + report assessment.

Task 1 — Shortest Path A → B (70 pts)
1a. Dijkstra — travel time criterion t (10 pts)
Points	Requirement
4	Dijkstra's algorithm correctly finds the shortest route by travel time for basic cases (direct connection, 1 transfer).
2	Correct GTFS data handling: graph construction from stop_times.txt, mapping stations to platforms (parent_station), filtering trips by calendar.txt (day of week + date range).
2	Correct time handling: waiting for a train is included in the cost, dwell times at stops (departure_time ≠ arrival_time), post-midnight times (24:xx:xx).
2	Correct output format: stdout contains successive segments (start stop, end stop, line name, departure time, arrival time); stderr contains the optimized criterion value and computation time.
1b. A* — travel time criterion t (25 pts)
Points	Requirement
8	A* correctly finds the optimal route (identical to Dijkstra) by travel time.
7	The heuristic is admissible: h(n) ≤ h*(n) for every node. The student can explain why the chosen heuristic never overestimates the true cost (e.g., Haversine / v_max with v_max ≥ maximum speed in the network).
5	A explores fewer nodes than Dijkstra (measured and demonstrated in the report or on stderr). If A explores the same number of nodes as Dijkstra, the heuristic is trivial (h=0) — fewer points awarded.
5	Correct handling of edge cases: calendar_dates.txt (holiday exceptions), pickup_type=1 (no boarding), no-solution scenario (algorithm terminates correctly).
1c. A* — transfer minimization criterion p (25 pts)
Points	Requirement
8	A* correctly minimizes the number of transfers (not travel time).
7	The heuristic is admissible for the transfer criterion. The student understands that a distance-based heuristic (Haversine/Euclidean) is not admissible for this criterion and uses an appropriate alternative (e.g., h=0, line-graph-based heuristic).
5	The cost function g(n) correctly counts transfers: changing lines at a station = +1 transfer, continuing on the same line = +0.
5	Correct results for routes requiring multiple transfers (≥2) and for routes with a direct connection (0 transfers).
1d. A* modifications (10 pts)
Points	Requirement
5	The proposed modification is reasonable and correctly implemented (e.g., bidirectional A*, better data structures, improved heuristic, pruning, landmark-based heuristics).
3	Experimental comparison with baseline A* — demonstrated improvement in computation time or solution quality (with concrete numbers/charts).
2	Description of the modification in the report: what was changed, why, and what effect it had.
Task 2 — TSP: Tabu Search (30 pts)
2a. Basic Tabu Search, unbounded T (10 pts)

2c. Aspiration criterion (5 pts)
Points	Requirement

Points	Requirement

3	Solution quality with sampling is not dramatically worse than with full scan (demonstrated experimentally).

FAQ
Q: Must A* return the same result as Dijkstra? Yes. With an admissible heuristic, A* guarantees optimality — the result should be identical to Dijkstra's. If it differs, the heuristic is inadmissible or there is a bug in the implementation.

Q: Can I use h=0 as the A* heuristic? Yes, but then A* = Dijkstra and you will not receive points for "fewer explored nodes" (1b). For criterion p, this is an acceptable solution.

Q: How should travel time be calculated — from the start time to arrival, or only time spent on trains? Travel time = time from the start moment (given as input) to the moment of reaching the destination station. It includes waiting for the train, travel time on trains, and waiting time during transfers.

Q: What if there is no connection? The algorithm should terminate correctly and report that no solution was found (it must not loop forever).

Q: In Task 2 (TSP), must I return to the starting station? Yes — the route must visit all stops in list L and return to A.
