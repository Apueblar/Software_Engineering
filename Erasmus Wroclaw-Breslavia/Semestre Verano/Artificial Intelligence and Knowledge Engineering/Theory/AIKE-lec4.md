2  Planning  •   Planning   –   a technique of problem - solving, it is aimed at  searching for a sequence of actions that causes the  transition of a system from an initial state to a goal state  •   Similarity   (planning   ↔   inference using a set of rules):  with some representations, both techniques use matching to  define a set of applicable rules or operations/actions  •   Difference :  –   representations for planning are usually more complicated  –   planning is a noncommutative system; it requires a   revocable  control strategy  –   conflict   subgoals   are produced

4  STRIPS   -   Stanford Research Institute  Problem Solver  •   STRIPS   –   a language:  –   classical, often used approach  –   it allows to define efficient planning algorithms  –   can be translated to state calculus  •   STRIPS   –   states and goals  –   s tate   –   conjunction of basic literals without variables (no  function symbols with fixed predicates, negation is possible)  •   example: At(Home)   ∧   Have(Milk)  •   Common assumption :   if a literal is not listed as a positive one in the  description of a state (True), it is assumed to be False (closedness of  the world)  –   goal : t he conjunction of literals, which may contain variables  •   example : At(x)   ∧   Sels ( x,Milk )  •   Common assumption :   variables contain existential quantifiers

5  STRIP  •   State  –   conjunction of atomic logical formulae  –   closed world assumption  •   Goal  –   partially described state  At(P1,JFK)   Ù   At(P2,SFO)  Ù   Plane(P1)   Ù   Plane(P2)  Ù   Airport(JFK)   Ù   Airport(SFO)

6  STRIPS representation of actions  (operators)  •   Operator   ( action )   in STRIPS consists of:  –   Property (description)   of an action   (1) :   name  and meaning description  –   Preconditions   (2) :   conjunction of true literals  (atoms)  –   Effect :   conjunction of literals   (true or false)  describing changes of situation after using the  action (operator )  –   Effect representation:  •   positive: ADD list   (3)   -   no duplication in the state  •   negative: DELETE list   (4)

7  STRIP Operators  •   Variables  –   logical  –   receive value only by unification  –   introduced only in the header  •   Example  Action(Fly(p, from, to),  PRECOND:At(p, from)   Ù   Plane(p)   Ù   Airport(from)  Ù   Airport(to)  EFFECT: ¬ At(p, from)   Ù   At (p, to))

9  STRIPS   –   plan representation  Plan   –   a data structure consisting of:  –   Set of plan steps   –   every step is one of the possible  operators  –   Set of constraints on the operators ordering :   is a  specification that one of the actions must occur  before another  –   set of binding constraints on the variables   -   they are  in the form   v   =   x , where   v   is a variable in a certain  step and   x   is a variable or constant  –   a set of causal links (connections) :   it describes the  objectives of the specific steps, e.g., a goal   S i   is   to  achieve a condition   c   of the state   S j

10  Principles of generating plans in  STRIPS  •   Apply the principle of the   least commitment  –   select only what is important now   –   leave the rest for  later  –   leave the order of steps (sequence) undefined, if it is  irrelevant at the given moment  –   a plan, in which some steps are ordered, and the  others are not, is a   Partial Order Plan   in contrast  to a   Total Order Plan   (Linear Order Plan)  •   Assign a fixed value to a variable :  example:   At( Robot,x )   At(Robot, Home)  •   Fully concrete plans: each variable has been  assigned a value

11  Solution in STRIPS  Solution:   executable   plan ,   ensuring goal achievement  •   It is easy to ensure a totally ordered plan without variables  •   It is not satisfactory because:  –   It is easier for   'planners’ to produce   a partially ordered plan than to  choose  an arbitrary one from the linearly ordered alternatives  –   some agents may perform actions in parallel  –   we may want to be able to manage the implementation more easily  of the plan in case other restrictions   occur  •   Therefore, the solution is a complete and coherent plan:  –   Complete   plan :  •   each precondition of each step is achievable by other steps  •   prerequisites are produced by other steps only when needed  –   Consistent plan :  •   includes no contradictions in the order of the actions and values of variables

13  Planning as searching  •   P lanning encompasses   a   ‘ search problem ’  ( selection of operators), which is   ubiquitous in   AI  –   problem of conflict   subgoals  –   to achieve a goal, a conjunction of   subgoals   achieved  by subplans is required  –   those subplans often   lead to conflicts in a desired  state ,   e.g ., (on A B) and (on B A)  –   such effects often occur when planning   is parallel  •   For   n   operators, there are   n ! possible  “orderings”  –   potentially high computational complexity

60  Planning as State - Space Search  •   Satisficing or Optimal Planning  –   satisficing planning : any plan is OK (cheaper ones  preferred)  –   optimal planning : plans must have a minimum cost  –   almost no overlap in the algorithms  •   Main techniques  –   explicit search   –   only heuristics are practical  •   progression: forward from the initial state to the goal  •   regression: backward from goal states to the initial state  –   SAT planning  –   symbolic search

61  E xplicit   search  •   Search across a set of states  –   states represented by propositions (complex logical  sentences)  –   propositional logic  •   Only heuristics are practical  –   progression: forward from the initial state to the goal  –   regression: backward from goal states to the initial  state

62  SAT Planning  •   SAT   -   algorithms that find satisfying assignments to CNF  (Conjunctive Normal Form) formulas  •   Formalisation of a plan as a propositional satisfiability  problem  –   propositional variables for states   –   v i - th state  –   propositional variables for operators   –   o i - th operator in a  sequence  –   to express a formula whose models are exactly the plans  •   Design choices:  –   SAT encoding, SAT solver, evaluation strategy  •   Examples: MiniSAT, Glucose, Lingeling

63  Symbolic Search  •   Search processes sets of states at a time  –   sequences of operators  –   across state sets reachable with a given cost.  –   search space represented by Symbolic Data Structures  •   e.g. binary decision diagrams (BDDs)  •   Decisions  –   search direction, algorithm, control (and heuristics)

64  Heuristics for Planning by Searching  •   Delete relaxation  –   ignoring all delete effects from operators  –   relaxed planning for calculating ‘distance’  •   Abstraction  –   dropping some distinctions between states, while preserving the  transition behaviour as much as possible  •   Constraint - based Heuristics  –   Landmarks  •   exploration   of constraints that hold in every solution of the task  –   Network   flows  •   properties   of   a   sequence   of   actions,   e.g.   balance: consumption vs production  –   Potential   heuristics  •   based   on   a linear combination of the features describing states
