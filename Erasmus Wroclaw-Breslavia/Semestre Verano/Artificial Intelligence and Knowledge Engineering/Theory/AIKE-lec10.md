Reinforcement Learning   (RL)   –   an idea  •   Reinforcement learning (RL) is  –   learning what to do  –   how to   map situations to actions  –   so as to maximise a   numerical reward   signal  •   The learner is not told which actions to take, as in most forms of machine  learning, but instead must discover which actions yield the most reward  by trying them  •   In the most interesting cases, actions may affect not only the immediate  reward, but also the next situation and all subsequent rewards  •   These two characteristics   –   trial - and - error search   and   delayed reward   –  are the two most important distinguishing features of reinforcement  learning

What makes reinforcement learning different  from other machine learning paradigms?  •   There is no supervisor, only a   reward   signal  •   Feedback is delayed, not instantaneous  •   Time really matters (sequential,   non   i.i.d   data! )  –   “ i.i.d .” means: independent and identically distributed variables  •   Agent’s actions affect the subsequent data it receives

•   Learning agent seeks to achieve a goal despite uncertainty  about its environment  •   The agent’s action can influence the future state  of the environment (e.g., the next location of the robot)  –   it affects   t he options and opportunities at a later time  •   The correct choice should take into account the delayed  consequences of actions, i.e., it requires foresight or planning  •   The effects of actions cannot be fully predicted   –   the agent  must monitor its environment frequently and react  appropriately  Learning a gents

An RL agent may include one or  more of these components:  •   Policy : agent’s   behaviour   function:  state   à   action  •   Value function : how good is each state  and/or action   ( prediction of future rewards )  •   Model : agent’s representation  of the environment, including states

RL Elements:   a   policy  •   Basic elements are: a   policy , a   reward function , a   value  function , and, optionally, a   model   of the environment  •   Policy   is the core of an RL agent in the sense that it alone is  sufficient to determine   behaviour  •   A   policy   –   is a mapping from perceived   states   of the  environment to   actions   to be taken in those states  (a kind of set of stimulus - response rules or associations)  •   A   policy   may be a simple function or lookup table, or may  involve extensive computation, such as a search process, or  maybe stochastic  deterministic :   a   =   π ( s )   or stochastic :   π ( a | s ) = P[ A t   =   a | S t   =   s ]

•   Reward function   defines the goal in an RL problem  •   It   maps   a perceived   state   (or state - action pair) to a single number  –   a   reward   ( a scalar feedback signal )  •   It defines what are good and bad events for a learning agent  •   It must necessarily be unalterable by the agent  –   It is   a property of the environment , not an agent  •   A reward function may be stochastic  •   A   reward   indicates the   intrinsic desirability   of a state  •   RL's objective is the   maximisation   of the   total reward in the long  run  RL Elements:   a   reward function   and  reward

•   In opposition to the   reward function , a   value function  (i.e.,   value   of a state ) specifies what   is good in the long run  •   Value function   is a prediction of future rewards  •   Used to evaluate the goodness/badness of states  •   and therefore to select between actions, e.g.:  •   State value   is the total amount of reward expected by an agent to  accumulate over the future states, starting from the given one  •   State value   indicates the   long - term   desirability of states after taking  into account the states that are likely to follow, and the rewards  available in those states  RL Elements: a   value function   (state value)

A   value function   role  •   We seek actions that bring about states of highest value, not  highest reward, because these actions obtain the greatest  amount of reward for us over the long run  •   It is hard to determine values; rewards are given directly by  the environment, but values   must be estimated and re -  estimated from the sequences of observations   an agent  makes over its entire lifetime  •   In fact, the most important component of almost all RL  algorithms is a method for efficiently estimating values

The RL framework  •   At each time step, an agent implements a mapping from  states to probabilities of selecting each possible action  •   This mapping is called the agent's   policy   and is denoted   Π t ,  where   Π t ( s,a ) , is the   probability of   a t = a   when   s t = s  •   RL methods specify how an agent changes its policy as a result  of its experience  •   The agent's goal is to   maximise   the total amount of reward it  receives over the long run  •   The use of a reward signal to   formalise   the idea of a goal is  one of the most distinctive features of   RL

Discounted return  •   An agent tries to maximise the sum of discounted rewards it  receives over the future, it chooses   a t   to maximise the  expected   discounted return :  where   γ   is a parameter called the discount rate, and 0≤   γ   ≤1  •   A reward received   k   time steps in the future is worth   γ k - 1   times  what it would be worth if it were received immediately  •   γ   < 1   –   the infinite sum has a finite value when { r k } is bounded  •   γ   = 0   –   an agent maximises immediate rewards  •   γ   = 1   –   an agent becomes more farsighted

How to   solve ?  •   Classical   optimisation   methods for sequential decision problems (e.g.,  dynamic programming ), can compute an   optimal solution   for any  opponent, but require as input a complete specification of that opponent,  including the probabilities of each of his moves in each board state  •   Let us assume that this information is not available  •   Such information can be estimated from experience, in this case, by  playing many games against the opponent  •   The best one can do is first to learn a model of the opponent's   behaviour ,  up to some level of confidence, and then apply dynamic programming to  compute an optimal solution given the approximate opponent model  •   This is not that different from some of the RL methods, see (Sutton and  Barto , 2020, Fig. 1.1, pp. 10)

Summary :   Tic - Tac - Toe   –   a potential solution  •   Dynamic programming   can compute an optimal solution for any  opponent, but a complete specification of the opponent is needed  –   i.e., also probabilities of making particular moves by the opponent  •   Assuming that such information is not available  •   This information can be estimated on the basis of experience   –   a number  of games can be played against the opponent  •   Good way: to learn a model of the opponent’s   behaviour   (with some level  of confidence) and then use dynamic programming to find an optimal  solution  Conclusion: It is a kind of reinforcement learning

Tic - tac - toe and RL with approximation  of value function  •   A table of numbers, one for each possible state of the game,  should be set, where:  –   each number   –   the latest estimate of the probability of our winning  from that state  –   the numbers   –   estimated states’ values  –   the table   –   the learned value function  •   If a state A has a higher value than state B, it means that state  A is ‘better’ than B. i.e., the current estimate of the  probability of our winning from A is higher than it is from B

Continuation:  let’s assume we always play X  •   For all states with three   Xs   in a row, the probability of winning is 1 (we won)  •   For all states with three   Os   in a row, the probability of winning is 0 (we lost)  •   The initial values we can set as 0.5, an equal chance of winning  •   We play many games against the opponent  •   While selecting the move, we examine the accessible states (from the  current one) and their current values in the table  •   Most of the time, we move   greedily   –   the selected move leads to a state  with the greatest value, that is, with the highest estimated probability of  winning  •   Occasionally, we select randomly from among the other moves  •   Such moves are called   exploratory   moves because they cause us to  experience states that we might otherwise never see

Some features of the method  •   The method converges to an optimal policy for playing the game  •   It is learning while interacting with the environment  •   There is a clear goal  •   The correct   behaviour   requires planning or foreseeing that takes  into account the delayed effects of one's choices.  •   It can achieve the effects of planning and looking ahead without  using a model of the opponent and without conducting an  explicit search over possible sequences of future states and  actions
