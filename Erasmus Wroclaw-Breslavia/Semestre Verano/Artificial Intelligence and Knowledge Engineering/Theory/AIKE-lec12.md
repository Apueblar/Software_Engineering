Semantic retrieval  •   Goal:  •   „to generate an ordered list of texts retrieved from a corpus in response to a query for a particular task",  •   Query-document matching function.  •   Problems:  •   Representation: query vs document,  •   Matching methods,  •   Process efficiency for very large collections.

Semantic retrieval – schema  •   Lexical retrieval  •   based on inverted index  •   from terms to documents,  •   keyword retrieval  •   IR: binary search model  •   Ranking based on term occurrences (global and local).  •   Re-ranking  •   for the k most suitable  •   Machine learning-based ranking adjustment (for the top k only)  •   Extracting the answers:  •   passage retrieval,  •   answer extraction.

Text Similarity Ranking: Problems  •   Question Answering (QA)  •   Information Retrieval – short queries  •   Semantic Retrieval  •   Question answering – queries similar to natural language questions.  •   Community Question Answering (CQA)  •   search in question and answer databases, e.g. Quora or Stack Overflow, „locating another user who has asked the same or similar question",  •   frequently-asked questions (FAQ).  •   Information Filtering  •   Queries express an information need.  •   Text Recommendation  •   suggesting texts (text objects) based on similarity.

Lexical retrieval  •   Exact term matching:  •   terms (query) vs terms (document).  •   Matching/ranking measures, e.g. BM25  •   BM25(q, d) = Σ_{t∈q∩d} log((N − df(t) + 0.5) / (df(t) + 0.5)) · (tf(t,d) · (k₁ + 1)) / (tf(t,d) + k₁ · (1 − b + b · l_d/L))  •   df(t) – number of documents containing t  •   N – collection size  •   tf(t,d) – t frequency in document d  •   ld – length of d  •   L – average document length in the collection  •   k₁ and b – parameters.

Measures for assessing relevance rankings  •   Cut-off precision and recall:  •   to the first k positions of the generated ranking, most often recall@100  •   MAP – Mean Average Precision,  •   MRR – Mean Reciprocal Rank  •   MRR = (1/|Q|) Σ_{i=1}^{|Q|} (1/rank_i)  •   Normalized Discounted Cumulative Gain (nDCG) (Lin, et al. 2021)  •   assumes a finite range of values of the relevance measure rel( ), IDCG – ideal value of DCG  •   DCG(R,q) = Σ_{(i,d)∈R} (2^{rel(q,d)} − 1) / log₂(i + 1)  •   nDCG(R,q) = DCG(R,q) / IDCG(R,q)

Query-document interaction models  •   Representation based models vs Interaction based models.  •   (a) a generic representation-based neural ranking model: query and document are independently encoded into dense vectors, and similarity is computed between them.  •   (b) a generic interaction-based neural ranking model: query tokens interact directly with document tokens through a matching matrix before computing a score.

Query-document interaction models – architectures  •   (a) Representation-based Similarity (e.g., DSSM, SNRM): separate encoders for query and document, similarity computed over their representations.  •   (b) Query-Document Interaction (e.g., DRMM, KNRM, Conv-KNRM): explicit token-level matching using match kernels.  •   (c) All-to-all Interaction (e.g., BERT): full cross-attention between all query and document tokens jointly.  •   (d) Late Interaction (i.e., ColBERT): tokens are encoded separately but matched via MaxSim operations at query time.  •   Source: ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction over BERT

monoBERT – idea  •   Re-ranking based directly on BERT.  •   Task: P(Relevant = 1 | d_i, q)  •   Architecture:  •   Texts → Inverted Index → Initial Retrieval → (Queries) → Candidate Texts → Reranker → Ranked List

monoBERT – schema  •   Cross-encoder  •   Input format: [[CLS], q, [SEP], d_i, [SEP]]  •   Query tokens and document tokens are concatenated and processed jointly through all BERT layers.  •   The [CLS] token representation is used to predict the relevance score.  •   Token embeddings, segment embeddings (E_A for query, E_B for document), and position embeddings are all summed as input.

monoBERT vs neural ranking models  •   Interactive models show higher scores  •   Attention-modeled Q&A token interactions  •   „Attention appears to serve as a one-size-fits-all approach to extracting signal from term interactions, replacing the various techniques used by pre-BERT interaction-based models" (Lin et al., 2021)  •   (a) Representation-Based: independent encoders, score from vector similarity.  •   (b) Interaction-Based: explicit token-level interaction matrix.  •   (c) monoBERT: full cross-encoder with joint attention over query and document.

Retrieval Augmented Generation (RAG)  •   Retrieval-Augmented Generation for Large Language Models: A Survey. (Gao et al., 2024)  •   RAG pipeline:  •   User submits a Query → Documents are indexed into Chunks/Vectors → Embeddings → Retrieval of Relevant Documents  •   Retrieved chunks are combined with the query → Prompt sent to LLM → Answer generated  •   Without RAG: model lacks recent knowledge, may hallucinate.  •   With RAG: model can cite specific retrieved chunks, answer is grounded in actual documents.

Retrieval Augmented Generation (RAG) – advantages  •   Allows for delivering the latest information to the model  •   Reduces hallucinations  •   Allows for using LLM as an assistant in a specific field (company documents, descriptions of the latest events)  •   Enables better interpretation of the response and indication of the source  •   Source: Retrieval-Augmented Generation for Large Language Models: A Survey. (Gao et al., 2024)

Retrieval Augmented Generation (RAG) – optimisation levels  •   The RAG pipeline can be optimized at different levels:  •   Document chunking  •   Rewriting or extending the query  •   Reranking with a larger model  •   Analysis of the generator's response and regeneration or search for missing documents  •   Naive RAG: User/Query → Indexing → Retrieval → Prompt + Frozen LLM → Output  •   Advanced RAG adds Pre-Retrieval (Query Routing, Query Rewriting, Query Expansion) and Post-Retrieval (Rerank, Summary, Fusion) stages.  •   Source: Retrieval-Augmented Generation for Large Language Models: A Survey. (Gao et al., 2024)

Retrieval Augmented Generation (RAG) – retrieval strategies  •   ITERATIVE: Provide more context information  •   Query → Retrieve → Generate → Judge → (Iterate N Times) → Response (Max Times / Threshold)  •   RECURSIVE: Break down complex problems step by step  •   Query → Retrieve → Generate → Query Transformation/Decomposition → Judge → (Max Depth/Threshold) → Response  •   ADAPTIVE: Flexible and active control of retrieval and generation  •   Query → Judge (Retrieve On Demand) → Retrieve → Generate → Judge → (Generate Special Token / Threshold) → Response  •   Source: Retrieval-Augmented Generation for Large Language Models: A Survey. (Gao et al., 2024)

Multiagent systems – example  •   A RAG pipeline where each component (query transformation, document retrieval, selection, generation) is treated as an agent with a separate reward function. It is optimized with reinforcement learning, maximizing the shared end reward.  •   MMOA-RAG framework (Chen et al., 2025):  •   Initial question q → Query Rewriter (trainable) → Sub-questions subq → Retriever (frozen) → Documents set D → Selector (trainable) → Selected set D_selected → Generator (trainable) → Predicted answer Ans_predict  •   Each agent has an individual reward (R_QR, R_S, R_G) and penalty (P_QR, P_S, P_G) combined into a Shared Reward against the Golden answer Ans_golden.

Agents  •   Types of agents (Yuheng Cheng et al., 2024):  •   Reflex Agent:  •   Rule-based Agent: explicit condition-action rules (A^B^C→Action 1, ...)  •   Learning-based Agent:  •   RL-based Agent: learns from environment feedback  •   Large Model-based Agent:  •   LMM-based Agent: combines multimodal perception with action  •   LLM-based Agent: uses a large language model as the reasoning core  •   AGI Agent: hypothetical future general intelligence agent

LLM-based Agents  •   An agent is a modular structure in which an LLM autonomously analyses a problem, makes decisions about actions, and executes them.  •   Four core components:  •   (1) Environment – Decision-making space  •   (2) Memory – short-term, long-term  •   (3) Tools – Function Calling, web search, API calls  •   (4) Planning and reasoning – Decomposition of tasks, self-reflection

LLM-based Agents – architecture  •   (Yuheng Cheng et al., 2024)  •   Memory: Short-term (prompt context) → summarized into → Long-term (external storage)  •   LLM core: retrieves from memory, plans, acts  •   Objective: goal driving the planning cycle  •   Action: interacts with the Environment  •   Feedback/Observation feeds back into Rethink  •   Tools available: Chat, Machine, APIs, Crawler  •   Environments: Computer, Game, Code, Simulation, Real-World

(2) Memory  •   Short-term memory – stores the current context and recent activities of the agent  •   prompt context  •   History of dialogue (memory buffer)  •   Context compression (through summarisation, distillation)  •   „LangChain enhances short-term memory efficiency by encapsulating crucial information from each interaction and preserving the most recurrent interactions" (Yuheng Cheng et al., 2024)  •   Memory capability of LLM-based agents:  •   Short-term Memory  •   Long-term Memory: Knowledge Graphs, Vector Databases, Relational Database Queries, API Calls  •   Memory Retrieval

(2) Memory – long-term and retrieval  •   Long-term memory – allows you to store important information between interactions (data about earlier stages of activity, user, ...)  •   knowledge bases and file-based memory repositories (e.g. memory pools)  •   vector storage of episodes – vector stores  •   Save state between sessions – memory persistence  •   Memory Retrieval – searching and extracting knowledge from external sources  •   Sourcing decisions, e.g. classifier,  •   Strategies for Preservation (Remembering) and Pruning (Forgetting).  •   Retrieval Augmented Generation  •   Analogy with human memory (Zhao, Jin & Cheng, 2023):  •   Sensory Memory → Input Embedding  •   Short-term Memory → Temporary information processed during task execution  •   Long-term Memory (Episodic + Semantic) → Stored in an external storage system  •   Training Memory: knowledge stored through model parameters during pre-training

(3) Function Calling  •   Allows the agent to perform actions outside the model: functions, APIs, databases, external programs  •   It allows the agent to act procedurally, not just generate text  •   Scheme:  •   recognizing the need to use the tool → calling the function → getting the result → analysing the result → deciding on the next action  •   Supervised fine-tuning on examples of tool use  •   Challenges: recognising when the tool is used, correcting the parameters of the functions/tools called

(3) Function Calling – mechanism  •   We provide the model with a JSON schema for the available functions → The model selects the function with arguments → The environment calls the appropriate tool.  •   Example (glaive-function-calling-v2):  •   SYSTEM: You are a helpful assistant with access to the following functions. Use them if required - { "name": "get_news_headlines", "description": "Get the latest news headlines", "parameters": { "type": "object", "properties": { "country": { "type": "string", "description": "The country for which to fetch news" } }, "required": ["country"] } }  •   USER: Can you tell me the latest news headlines for the United States?  •   ASSISTANT: <functioncall> {"name": "get_news_headlines", "arguments": '{"country": "United States"}'}  •   FUNCTION RESPONSE: {"headlines": ["Biden announces new vaccine mandates", "Hurricane Ida devastates Louisiana", "Apple unveils new iPhone", "NASA's Perseverance rover collects first Mars rock sample"]}  •   ASSISTANT: Here are the latest news headlines for the United States: 1. Biden announces new vaccine mandates 2. Hurricane Ida devastates Louisiana 3. Apple unveils new iPhone 4. NASA's Perseverance rover collects first Mars rock sample  •   Dataset: https://huggingface.co/datasets/glaiveai/glaive-function-calling-v2

(4) Planning and reasoning  •   In-context learning – a cycle: generate → evaluate → correct. Enables plan adaptation during generation (e.g. ReAct (Yao et al. 2023), Reflexion (Shinn et al. 2023), CoT)  •   ReAct ("Think and Do" Agent):  •   The agent has a thought: "To answer this, I need more info."  •   It takes an action: maybe searches the web or runs a calculation.  •   It sees the observation: the result of that action.  •   Reflexion ("Learn From Mistakes" Agent):  •   Generate an initial answer (often using a ReAct-style process).  •   Critique itself: "Wait, does this actually make sense?"  •   Refine the answer based on that critique.

(4) Planning and reasoning – training methods  •   Supervised methods and reinforcement learning – teach the agent (de facto LLM) to better plan or correct logic through information from the environment or giving a pattern (ground truth):  •   Supervised: correct steps and plan structure (e.g. Process Supervision, Hinting),  •   Reinforcement: improving strategies with feedback from the environment (e.g. Dialogue Shaping, REX)  •   Multimodule and multiagent systems – combining separate planning, memory, and execution modules (e.g. planner–executor architectures)

(4) Reasoning – example: gsm8k  •   System prompt for Chain-of-Thought with reflection:  •   You are an AI assistant that uses a Chain of Thought (CoT) approach with reflection to answer queries.  •   Follow these steps:  •   Think through the problem step by step within the <thinking> tags.  •   Reflect on your thinking to check for any errors or improvements within the <reflection> tags.  •   Make any necessary adjustments based on your reflection.  •   Provide your final, concise answer within the <output> tags.  •   Important: The <thinking> and <reflection> sections are for your internal reasoning process only. Do not include any part of the final answer in these sections. The actual response to the query must be entirely contained within the <output> tags.  •   Output format: <thinking> → <reasoning> → <reflection> → <adjustment> → <output>

(4) Reasoning – example: gsm8k – task and answer  •   Question: A craft store makes a third of its sales in the fabric section, a quarter of its sales in the jewelry section, and the rest in the stationery section. They made 36 sales today. How many sales were in the stationery section?  •   Ground truth answer: Thus, there were 36 - 12 - 9 = <<36-12-9=15>>15 sales in the stationery section.  •   Generated output:  •   <thinking> To find the number of sales in the stationery section, I need to first calculate the number of sales in the fabric and jewelry sections. The store makes a third of its sales in the fabric section, which is 1/3 of 36 sales. I can calculate this as 36 * 1/3 = 12 sales in the fabric section. The store makes a quarter of its sales in the jewelry section, which is 1/4 of 36 sales. I can calculate this as 36 * 1/4 = 9 sales in the jewelry section. Since the rest of the sales are in the stationery section, I can subtract the sales from the other two sections from the total number of sales to find the number of sales in the stationery section. </thinking>  •   <reasoning> 1. Calculate the number of sales in the fabric section: 36 * 1/3 = 12 2. Calculate the number of sales in the jewelry section: 36 * 1/4 = 9 3. Calculate the number of sales in the stationery section: 36 - 12 - 9 = 15 </reasoning>  •   <reflection> Upon reviewing my reasoning, I noticed that my calculations seem correct, but I should ensure that I understand the question correctly. The question asks for the number of sales in the stationery section, and I believe I have correctly calculated that. However, I should double-check my math to make sure it's accurate. </reflection>  •   <adjustment> Upon re-examining my math, I am confident that my calculations are correct. The fabric section makes up 1/3 of the sales, the jewelry section makes up 1/4, and the rest is the stationery section. My math checks out, and I am confident in my answer. </adjustment>  •   <output> 15 </output>  •   Messages structure: [{"role": "system", "content": system_prompt}, {"role": "user", "content": task}, {"role": "assistant", "content": recording of the generated output}]

TORA – tool integration and reasoning  •   ToRA: A Tool-Integrated Reasoning Agent for Mathematical Problem Solving (Gou et al., 2024)  •   Combines Chain of Thought (CoT) reasoning with programmatic tool use  •   Chain of Thought: step-by-step natural language reasoning  •   PAL: Program-aided Language Models (Gao et al., 2023): code-based reasoning  •   Combination of reasoning and complex tool use via program code  •   Universality of the solution, precision and flexibility of the combination  •   Training process:  •   knowledge distillation + remotely (weakly) supervised training of an LLM

TORA – reasoning schemas  •   Tool integration as a combination of Chain of Thought and Program-based approaches  •   (a) Rationale-based: natural language reasoning only → may produce incorrect symbolic steps (marked ✗)  •   (b) Program-based: pure code solution → may fail due to syntax errors (marked ✗)  •   (c) Tool-integrated Reasoning (ToRA format):  •   r₁: natural language rationale suggesting to use Sympy  •   a₁: Python code using sympy to solve the problem  •   o₁: output from code execution (e.g. [-5, -5, 1, 1, 4, 4])  •   r₂: final natural language answer based on the output (marked ✓)  •   Example problem: Suppose that the sum of the squares of two complex numbers x and y is 7 and the sum of their cubes is 10. List all possible values for x + y.

TORA – two stage training  •   Stage 1: Imitation Learning  •   Problem → strong LLM generates tool-integrated reasoning trajectories  •   Valid trajectories collected into ToRA-Corpus  •   Fine-tune student model M on this corpus  •   Stage 2: Output Space Shaping (weakly supervised finetuning)  •   Model M samples multiple output trajectories for each problem  •   Trajectories with errors (marked ✗) are sent to a Teacher model M' for correction  •   Corrected valid trajectories (marked ✓) are used for further fine-tuning  •   Final result: ToRA model, trained to combine reasoning and tool use reliably

TORA – reasoning example 1  •   Question: Solve the inequality (x² − 25) / (x + 5) < 0.  •   Solution: Let's use 'sympy' to solve the inequality:  •   from sympy import symbols, simplify  •   from sympy.solvers.inequalities import solve_univariate_inequality  •   from sympy.core.relational import StrictLessThan  •   def solve_inequality():  •       x = symbols('x')  •       expression = (x**2 - 25) / (x + 5)  •       inequality = StrictLessThan(expression, 0)  •       solution = solve_univariate_inequality(inequality, x, relational=False)  •       simplified_solution = simplify(solution)  •       return simplified_solution  •   result = solve_inequality()  •   print(result)  •   Output: Union(Interval.open(-oo, -5), Interval.open(-5, 5))  •   The answer is (-∞, -5) ∪ (-5, 5)

TORA – reasoning example 2  •   Question: What real values of x are not in the domain of f(x) = 1 / (|x²−6x+8| + |x²+x−6|)?  •   Solution: The domain of the function is all real numbers, so we need to find the values of x for which the denominator is zero.  •   from sympy import symbols, Abs, solveset, S  •   from sympy.core.relational import Ne  •   def non_domain_values():  •       x = symbols('x')  •       roots1 = solveset(Ne(x**2 - 6*x + 8, 0), x, domain=S.Reals)  •       roots2 = solveset(Ne(x**2 + x - 6, 0), x, domain=S.Reals)  •       non_domain_values = S.Reals - (roots1.union(roots2))  •       return non_domain_values  •   result = non_domain_values()  •   print(result)  •   Output: {2}  •   The real value of x that is not in the domain of the function is 2.
