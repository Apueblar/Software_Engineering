Windows Server Platform & Virtualization

Foundational
Summary
Windows Server 2025 is the server OS at the core of this course. Three installation flavors exist: Desktop Experience (full GUI), Core (CLI-only), and Nano (container-only). Virtualization comes in two types: Type I (bare-metal hypervisor — Hyper-V) and Type II (hosted — VirtualBox). Containerization shares a single OS kernel across isolated workloads.
⚡ Type I — Bare-Metal Hypervisor
  • Runs directly on hardware
  • Examples: Hyper-V, VMware ESX, KVM
  • Guest partitions sit above hypervisor layer
  • Better performance, used in production
  • Intel Hyperthreading → each physical core = 1 Logical Processor (LP)
🪟 Type II — Hosted Hypervisor
  • Runs as software on top of a host OS
  • Examples: VirtualBox, VMware Player
  • Each guest OS has its own VMM layer above host
  • Easier to set up, used for development/testing
  • Extra OS overhead = slower than Type I
🖥 Desktop Experience
  • Full GUI (Explorer, MMC, etc.)
  • RAM: min 2 GB
  • Familiar, easiest to manage locally
  • Higher attack surface & resource use
⌨ Server Core
  • Command-line only — no GUI
  • RAM: min 512 MB (1024MB to install)
  • Same roles as Desktop Experience
  • Managed via sconfig, PowerShell, RSAT
🪄 Nano Server
  • Container-only, headless, extremely small
  • RAM: ~128 MB per instance
  • Supports only select roles: DNS, web server
  • Example: 3400 Nano VMs on a single 8×20-core/1TB RAM host
Server 2025 Editions
EditionOSEs AllowedNotes
DatacenterUnlimitedFor high-density virtualisation environments
Standard2Most common; full feature set
Essentials125 users / 50 devices cap; small businesses
Storage Server—OEM only; optimised for NAS/SAN scenarios
Hyper-V Server—Free; hypervisor only, no Windows Server roles
🔧 Roles vs Features
  • Role — complex function (e.g. DNS, DHCP, Domain Controller); a group of dependent services
  • Feature — single capability not normally exposed to clients (e.g. BitLocker)
  • Roles can depend on features; "features on demand" must be installed from mounted media
  • Managed via Server Manager — multi-server console
📋 Min. Requirements (Server 2025)
  • CPU: x86-64, 1.4 GHz min, NX/DEP/SLAT
  • RAM: 2 GB (GUI) / 512 MB (Core)
  • Disk: 32 GB (more if RAM > 16 GB)
  • Install via: DVD, USB, or WDS (network-based)

Domain Environment & Active Directory Fundamentals

Core AD
Summary
Active Directory (AD DS) is the central directory service for Windows domains. A domain provides centralized authentication via Kerberos and a single account that works domain-wide. Multiple domains form trees; multiple trees form a forest. Logical structure (OUs, domains) maps separately from physical structure (sites, DCs).
Diagram — Kerberos Authentication Flow (Single Sign-On)
🧱 AD Physical Objects
  • Domain Controller (DC) — runs AD DS, authenticates users
  • Data Store — C:\Windows\NTDS\ntds.dit
  • Global Catalog (GC) — partial replica of all objects in forest
  • RODC — Read-Only Domain Controller (branch offices)
🧩 AD Logical Objects
  • Schema — defines object types and attributes
  • Domain — security and admin boundary
  • Tree — parent/child domains with contiguous namespace
  • Forest — collection of trees; single schema
  • OU (Organizational Unit) — container for delegation & GPO linking
AD Object Naming Formats
FormatExampleScope
Distinguished Name (DN)cn=Sarah,ou=Marketing,DC=contoso,DC=internalUnique domain-wide
Relative DN (RDN)ou=MarketingRelative to parent only
Canonical Namecontoso.internal/Marketing/SarahHuman-friendly path
UPNsarah@contoso.internalLogin; unique in forest
SAM Account Namecontoso\sarahPre-Win2000 logon; legacy
⚠️ OUs vs Containers — Critical Difference
  • Containers (e.g. built-in Users, Computers, Built-in): cannot be nested, cannot have permissions assigned, cannot have GPOs linked
  • OUs: can be nested, can have permissions delegated, can have GPOs linked — this is the key practical difference
  • PowerShell: New-ADOrganizationalUnit -Name Sweden -Path "DC=contoso,DC=internal"
💻 Promote a DC via PowerShell
Install-WindowsFeature AD-Domain-Services
Import-Module ADDSDeployment
# First DC in a new forest:
Install-ADDSForest -DomainName contoso.internal -InstallDNS
# Additional DC in existing domain:
Install-ADDSDomainController -DomainName contoso.internal -InstallDNS

User Accounts, Computer Accounts & Groups

Identity
Summary
Users authenticate with a UPN or SAM account name. Computers have their own accounts with auto-rotating passwords. Groups come in two types (Security vs Distribution) and three scopes (Domain Local, Global, Universal). The A-G-DL-P strategy provides a recommended pattern for assigning permissions.
Domain Local
  • Visible/usable only in its own domain
  • Can hold objects from the entire forest
  • Used to assign permissions to resources
  • Think: "the lock on the resource"
Global
  • Visible from all forest domains
  • Can only contain objects from its own domain
  • Used to gather users by role/dept
  • Think: "the key that represents users"
Universal
  • Visible from all forest domains
  • Can contain objects from entire forest
  • Used to combine global groups across domains
  • Stored in the Global Catalog
Mnemonic — A-G-DL-P Strategy
Accounts → Global groups → Domain Local groups → Permissions
In multi-domain forests, add Universal: A → G → U → DL → P
🖥 Computer Accounts
  • Each domain computer has its own account with a random, auto-rotating password
  • Add via PowerShell: Add-Computer -ComputerName cl2 -DomainName "contoso.com" -Restart
  • Common problems: reinstalling OS creates a new account (password mismatch); excessive time diff breaks Kerberos
👤 Create a User (PowerShell)
New-ADUser Anna -SamAccountName Anna `
  -UserPrincipalName "annas@contoso.com" `
  -Path "OU=Sweden,DC=contoso,DC=internal" `
  -DisplayName "Anna Svensson" `
  -AccountPassword (ConvertTo-SecureString `
    -AsPlainText "P@sswOrd" -Force) `
  -Enabled $true

File & Folder Permissions (NTFS)

Security
Summary
NTFS permissions apply to files and folders on NTFS or ReFS volumes only (not FAT/FAT32). Every securable object has an ACL. Permissions are cumulative from all group memberships, but explicit Deny always wins. When accessing via a network share, both NTFS and Share permissions apply — the most restrictive (lowest common) result wins.
📋 Permission Evaluation Rules
  • Principle of least privilege — only explicitly assigned permissions apply
  • Implicit deny — no permission assigned = no access
  • Permissions from user + all groups are cumulative (additive)
  • Explicit Deny always wins over any Allow — even Full Control
  • Example: Read::Deny + Full Control::Allow → no read for anyone (even admins), but write works
🌐 NTFS + Share: The Combination Rule
  • Local access (C:\profiles) → only NTFS permissions apply
  • Network access (\\dc1\profiles) → both NTFS and Share apply
  • Effective = the most restrictive (lowest common) of the two
  • Microsoft best practice: set Share to Everyone::Full Control::Allow; manage restriction via NTFS only
Copy & Move Behavior — Permission Inheritance
📌 Permission Inheritance Key Points
  • ACL set on a parent folder propagates to subfolders/files automatically
  • Inherited permissions cannot be directly changed at the child — change at source
  • Inheritance can be disabled; you then choose to delete or convert to explicit (direct) permissions
  • ⚠️ Never remove permissions for Administrators and SYSTEM
  • Scope can be fine-tuned: "this folder only", "subfolders and files", "files only", etc.

PowerShell Fundamentals

Scripting
Summary
PowerShell is a command-line shell + scripting language using Verb-Noun naming conventions (e.g. Get-Service). It's the recommended management tool for Windows Server. Modern cross-platform "PowerShell" differs from legacy "Windows PowerShell" — check with $PSVersionTable.
🔍 Discovery Commands
  • Get-Command *Net* — wildcard search
  • Get-Help Get-NetAdapter -Examples
  • Get-Service | Get-Member — inspect properties/methods
  • Update-Help — refresh local help files
  • Get-Verb — list all allowed verbs
🔀 Loops
  • for — classic counter loop
  • foreach — iterates a collection: foreach ($id in $ids){...}
  • Foreach-Object — pipeline: Get-NetAdapter | Foreach-Object {$_.name}
  • While — condition checked before iteration
  • Do...While — condition checked after (always runs at least once)
# Pipeline example — list all running services with display name and startup type
Get-Service | Where-Object Status -eq Running | Select-Object -Property DisplayName,StartupType | Format-Table

# Execution policy — bypass for current session only
Set-ExecutionPolicy Bypass -Scope Process

function Get-ServerInfo {

Group Policies — Part 1 (Fundamentals)

GPO
Summary
Group Policy uses the Windows Registry as its configuration database. GPOs apply settings to computers and users in a defined order: Local → Site → Domain → OU. The last applied wins in a conflict. RSoP shows the final effective combination of all policies.
Diagram — GPO Application Order (Last Applied Wins)
⏱ GPO Refresh Timing
  • Computer settings: applied at startup, refreshed every 90–120 min
  • User settings: applied at logon, refreshed every 90–120 min
  • Software installation: only at startup/logoff — NOT via background refresh
  • Force refresh manually: gpupdate /force
🏗 GPO Structure
  • Two top-level: User Configuration + Computer Configuration
  • Each has: Software settings, Security settings, Administrative Templates
  • Managed via GPMC (Group Policy Management Console)
  • Applied to objects via GPO links at Site/Domain/OU
07 📐

Group Policies — Part 2 (Templates, Scope & Testing)

GPO
Summary
Administrative Templates (ADMX/ADML) define and describe settings. A GPO's physical files live in two places: the Group Policy Container (GPC) in AD and the Group Policy Template (GPT) in SYSVOL. Inheritance can be overridden with Block Inheritance (on an OU) and Enforce/No Override (on a GPO link).
📁 ADMX/ADML Template Files
  • ADMX — defines the actual settings (language-neutral)
  • ADML — translated/localized description text
  • Local: C:\Windows\PolicyDefinitions
  • Domain Central Store: C:\Windows\SYSVOL\domain\Policies\PolicyDefinitions
🧱 GPO Physical Storage
  • GPC (Group Policy Container) — stored in Active Directory; contains metadata and version
  • GPT (Group Policy Template) — stored in SYSVOL; contains actual policy files
  • Both must stay in sync — version mismatch causes inconsistency
🚫 Block Inheritance
  • Set on an OU
  • Prevents parent-container GPOs from applying
  • Can be overridden by Enforce
🔒 Enforce (No Override)
  • Set on a GPO link
  • Pushes settings through Block Inheritance
  • The strongest override available
🎯 Security Filtering
  • Restricts which groups the GPO applies to
  • Read + Apply permissions required
  • Delegation can explicitly exclude a group
📊 Group Policy Results
  • Shows what actually applied to a real target
  • Requires access to the target computer
  • User must have logged on there at least once
  • Real (not simulated) result
🔬 Group Policy Modelling
  • A simulation — target doesn't need to exist
  • More parameters → more accurate simulation
  • Great for planning and testing before deployment
  • Runs as a service on the DC

GPO Advanced — Software, Folder Redirection & PSOs

GPO
📦 Software Deployment via GPO
  • Only .msi format natively supported (MSIX on Server 2019+)
  • Does NOT refresh via gpupdate — only at startup/logon
  • Assigned (Computer): installs at startup, user cannot remove
  • Assigned (User): installs at logon, user cannot remove
  • Published (User only): appears in Control Panel; user can install/uninstall
  • ⚠️ Published is NOT available under Computer Configuration
  • Always use UNC path (\\dc1\install\) — never local path
📂 Folder Redirection
  • Transparently moves user profile folders (Documents, Desktop, etc.) to a network share
  • User path appears unchanged — fully transparent
  • Path: User Configuration > Policies > Windows Settings > Folder Redirection
  • Basic: all users → same root path
  • Advanced: different paths by security group
  • ⚠️ Do NOT redirect AppData(Roaming) — conflicts with roaming profiles
  • Enable Offline Files (CSC) for disconnected use
Password Settings Objects (Fine-Grained Password Policy)
The domain can only have one password policy per domain (from domain-level GPO). PSOs allow multiple policies for different users/groups in the same domain. PSOs are applied directly to users or security groups — never to OUs. When multiple PSOs apply to the same user, the one with the lower msDS-PasswordSettingsPrecedence value wins. 
# Create a PSO with PowerShell
New-ADFineGrainedPasswordPolicy -Name "ServiceAccounts-PSO" -Precedence 10 `
  -MinPasswordLength 20 -ComplexityEnabled $true `
  -LockoutThreshold 5 -LockoutDuration "00:30:00"

# Assign to a group
Add-ADFineGrainedPasswordPolicySubject -Identity "ServiceAccounts-PSO" -Subjects "SVC_Accounts"

# Check effective policy for a user
Get-ADUserResultantPasswordPolicy -Identity SVC_Accounts

AD Replication, Sites & FSMO Roles

Advanced AD
Summary
AD replication keeps all DCs in sync. Intra-site replication is change-triggered and propagates in under 5 minutes. Inter-site replication is schedule-driven (default: every 180 minutes). Five FSMO roles handle operations that cannot safely run on multiple DCs simultaneously.
🏠 Intra-Site Replication
  • Change-triggered — near real-time
  • Full propagation: under 5 minutes
  • Protocol: IP/RPC
  • Topology: ring + shortcuts, auto-managed by KCC
  • No admin configuration needed
🌍 Inter-Site Replication
  • Schedule-driven — default: every 180 min
  • Configured manually in AD Sites & Services
  • Protocol: IP/RPC (preferred) or SMTP (non-domain data only)
  • Diagnostic: repadmin /showrepl
  • Represents physical network topology
FSMO Roles — One per Domain / Forest
RoleScopeResponsibility
PDC EmulatorPer domainTime sync for all DCs; first to learn password changes; fallback for auth
RID MasterPer domainIssues pools of RIDs used to build unique SIDs for new objects
Infrastructure MasterPer domainTracks identifiers for objects referenced from other domains
Domain Naming MasterPer forestAdds/removes domains in the forest (AD Domains and Trusts)
Schema MasterPer forestProcesses all changes to the AD schema (schmmgmt.dll)
⚠️ Critical FSMO Seizure Rule: After seizing a failed DC's FSMO role onto another DC, you must NEVER bring the original DC back online. It still believes it holds the role and will cause immediate conflicts and data corruption. 
# Check current FSMO role holders
netdom query fsmo
Get-ADDomain | Select-Object PDCEmulator, RIDMaster, InfrastructureMaster
Get-ADForest | Select-Object DomainNamingMaster, SchemaMaster

# Transfer a role (graceful — old DC still online)
Move-ADDirectoryServerOperationMasterRole -Identity DC02 -OperationMasterRole PDCEmulator

# Seize a role (old DC has failed — NEVER bring it back!)
Move-ADDirectoryServerOperationMasterRole -Identity DC02 -OperationMasterRole PDCEmulator -Force

DNS Server

Networking
Summary
DNS translates hostnames to IPs and enables AD service discovery via SRV records. AD is entirely dependent on DNS — broken SRV records cause logon failures, GPO failures, and replication failures. The _msdcs subdomain stores AD-specific service records separately for independent replication and delegation.
📋 Zone Types
  • Primary — writable master copy
  • Secondary — read-only; updated via zone transfer
  • Stub — NS and A records only; delegates to authoritative server
  • AD-Integrated — stored in AD, replicates with AD automatically; preferred for domain zones
🔤 Key Record Types
  • A — hostname → IPv4
  • AAAA — hostname → IPv6
  • CNAME — alias → another name
  • MX — mail server for a domain
  • NS — authoritative name server for a zone
  • SRV — service location (LDAP, Kerberos) ← critical for AD
  • PTR — IP → hostname (reverse lookup)
🔁 Recursive Query
  • Client asks resolver for a final answer
  • Resolver does all the work on behalf of client
  • Used: workstation ↔ its configured DNS server
  • Returns: actual IP or NXDOMAIN
🔀 Iterative Query
  • Server returns a referral, not a final answer
  • "I don't know — try that server instead"
  • Used: between DNS servers during external resolution
  • Chain: root → TLD → authoritative server
💡 Why _msdcs exists: Created automatically when a domain installs. Contains DC locator, Global Catalog locator, and PDC Emulator SRV/CNAME records. Kept separate so it can be independently replicated to all DNS servers in the forest and delegated without touching the main domain zone.
⚠️ AD SRV Records — If These Break, Everything Breaks
  • DC lookup: _ldap._tcp.contoso.com
  • Kerberos: _kerberos._tcp.contoso.com
  • Missing/wrong SRV records → failed logon, GPO failures, replication failures
  • AD-integrated zone stores SRV records in AD; they replicate automatically

Certificate Services (PKI / AD CS)

Security
Summary
PKI provides Confidentiality, Integrity, Authenticity, and Non-repudiation. A Certification Authority (CA) issues certificates that bind a public key to an identity. Best practice: offline Root CA + online Enterprise Issuing CA (two-tier hierarchy). Certificate revocation is checked via the CRL downloaded from the CDP.
Stand-alone CA vs Enterprise CA
FeatureStand-alone CAEnterprise CA
Domain requiredNoYes
Certificate templatesNoYes
GPO autoenrollmentNoYes
Publishes CRL/AIA to ADNoYes
IssuanceManual approval (default)Automatic (if template allows)
Best used asOffline Root CAIssuing CA for domain members
🔗 CDP vs AIA
  • CDP (CRL Distribution Point): where clients download the CRL to check if a cert is revoked
  • AIA (Authority Information Access): where clients download the issuing CA cert to build the trust chain
  • Both: publish to AD (domain only) or HTTP (all clients)
  • Get-CACrlDistributionPoint / Get-CAAuthorityInformationAccess
⚙️ Key Install Decisions (cannot change later)
  • Computer name + domain (part of every issued cert)
  • CA type (Root vs Subordinate)
  • Key length: 4096-bit RSA recommended for roots
  • Hash algorithm: SHA-256 minimum (SHA-1 deprecated)
  • Validity period: Root 10–20 yrs; Issuing: ~5 yrs
⚠️ Offline Root CA Pitfall: If taken offline without pre-publishing a long-validity CRL (6+ months) reachable over HTTP (not just LDAP), all certificates it ever signed will start failing validation once the old CRL expires. Always publish via HTTP.
🔑 Key Archival / Recovery
  • CA can store an encrypted copy of the private key — only for encryption certs (e.g. EFS), never for signing/authentication keys
  • Requires a Key Recovery Agent (KRA) certificate
  • Used when keys are lost: profile deleted, OS reinstall, disk failure, device theft
  • Best practice: KRA on dedicated secure account; exported cert kept offline; tested periodically

Windows Firewall, IPSec & OpenSSH

Security
Summary
Windows Firewall is a stateful, host-based firewall (default: block all inbound, allow all outbound). It has three network profiles: Domain (auto; DC reachable), Private, and Public. IPSec authenticates/encrypts packets between two hosts. OpenSSH is cross-platform, fully scriptable remote access, pre-installed on Server 2025.
🌐 Domain Profile
  • Auto-applied when a DC is reachable
  • Cannot be set manually
  • Usually least restrictive for internal traffic
  • Check: Get-NetConnectionProfile
🏠 Private Profile
  • Internal/home networks
  • Set manually by an admin
  • Moderately restrictive
🔒 Public Profile
  • Default for unidentified networks
  • Most restrictive
  • Applied automatically when no domain/private match
IPSec — Enforcement Levels
ModeBehaviourUse For
Request AuthenticationTries IPSec; falls back to unprotected if peer can't authenticateInitial rollout, testing
Require AuthenticationRefuses unprotected traffic; peer must have a matching rule or communication failsProduction, after verified rollout
⚠️ Critical IKEv2 Cert Requirement: The machine cert MUST include EKU "IP Security IKE Intermediate" (OID 1.3.6.1.5.5.8.2.2). Standard Computer or Web Server templates do NOT include this. IKE negotiation will silently fail with no logged error. Fix: duplicate the "IPSec (Offline Request)" template, add the EKU, enroll on both machines before configuring the rule.
🔑 OpenSSH Key Auth — Critical Location
  • Standard user: C:\Users\<username>\.ssh\authorized_keys
  • Administrators group member: C:\ProgramData\ssh\administrators_authorized_keys
  • Admin file requires strict ACL — if permissions too broad, sshd silently ignores it
  • Set via: icacls.exe granting only Administrators:F and SYSTEM:F
💻 Enable OpenSSH (Server 2025)
  • Pre-installed by default on Server 2025
  • Default port: TCP 22 (predefined firewall rule created automatically)
  • Default shell: cmd.exe — change via registry key HKLM:\SOFTWARE\OpenSSH\DefaultShell
  • Generate key pair: ssh-keygen -t ecdsa
# Enable sshd service
Get-Service -Name sshd | Set-Service -StartupType Automatic
Start-Service sshd

# Restrict SSH access in sshd_config
AllowGroups contoso\sshusers contoso\serveroperators

# Change default shell to PowerShell 7
New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell -Value "C:\Program Files\PowerShell\7\pwsh.exe"
Restart-Service sshd

📝 Groups & Permissions
1. Which group scope can contain user accounts and groups from any domain in the forest, but is itself visible only within its own domain?
AGlobal group
BDomain Local group
CUniversal group
✅ C. Universal groups are visible from all forest domains AND can hold objects from the entire forest. Domain Local groups can hold forest-wide objects but are only visible within their own domain — that's the distinction here.
2. A folder's NTFS permission is G_Accounting::Full control::Allow and its Share permission is Domain Users::Read::Allow. What is the effective permission when accessing the folder via \\dc1\reports?
AFull control, because NTFS permissions always override Share permissions
BRead, because the most restrictive of the two applicable permissions applies
CFull control, because Share permissions are ignored when NTFS permissions exist
✅ B. Network access applies BOTH permission sets simultaneously. The effective permission is always the most restrictive (lowest common) result — here, Read wins over Full Control.
3. Which statement about Organizational Units (OUs) versus Containers is correct?
AContainers can have Group Policy Objects linked to them, just like OUs
BOUs can be nested and have permissions/GPOs assigned; containers cannot
CContainers and OUs are functionally identical, differing only in icon
✅ B. OUs can be nested, have permissions delegated, AND have GPOs linked. Built-in Containers (Users, Computers, Built-in) can do none of these — this is the key practical difference.
📝 Group Policies
4. An administrator wants software to install automatically on 200 computers at next startup, with users unable to uninstall it. Which combination is correct?
APublished deployment under Computer Configuration
BAssigned deployment under Computer Configuration
CAssigned deployment under User Configuration, applied at logon
✅ B. Assigned (Computer Configuration) installs at startup automatically and users cannot remove it. Published is NOT available under Computer Configuration — only Assigned is. Published (User only) can be uninstalled by users.
5. Which Group Policy Client Side Extension is notable for NOT being refreshable using gpupdate?
AFolder Redirection
BAdministrative Templates
CSoftware Installation
✅ C. Software Installation is one of the few CSEs that does NOT refresh via gpupdate. Computer assignments only apply at startup; User assignments only apply at logon.
6. A Password Settings Object (PSO) can be linked directly to which of the following?
AAn Organizational Unit only
BUsers or security groups, but never OUs
CThe domain root only
✅ B. PSOs are applied directly to users or security groups — NEVER to OUs. This is a critical distinction from regular domain password policy (which can only exist at domain level via GPO).
7. Two PSOs apply to the same user. Which one takes effect?
AThe one created most recently
BThe one with the higher msDS-PasswordSettingsPrecedence value
CThe one with the lower msDS-PasswordSettingsPrecedence value
✅ C. Lower precedence number = higher priority. If two PSOs conflict, the one with the lower msDS-PasswordSettingsPrecedence value wins. Think: "1 beats 10."
📝 Replication & FSMO
8. What is the default interval for AD inter-site replication (assuming default settings)?
AEvery 15 minutes
BEvery 180 minutes
CChange-triggered, near real-time
✅ B. Inter-site replication defaults to every 180 minutes (3 hours). Change-triggered near real-time is intra-site replication — a very common exam trap.
9. Which FSMO role is responsible for time synchronization across all domain controllers in a domain and is the first to learn of password changes?
ARID Master
BPDC Emulator
CInfrastructure Master
✅ B. The PDC Emulator synchronizes time for all DCs in the domain (critical for Kerberos which fails if clocks drift >5 min) and is the first to learn of password changes, acting as an auth fallback.
10. After seizing a failed DC's FSMO role onto another DC, what must the administrator do regarding the original (failed) DC?
ABring it back online as soon as possible to restore redundancy
BNever bring it back online, since it still believes it holds the role
CRe-promote it immediately as a Global Catalog server
✅ B. After seizing an FSMO role, the original DC MUST NEVER come back online. It still believes it owns the role and will cause conflicts. The original must be decommissioned.
📝 DNS
11. Which DNS record type allows clients to locate AD services such as LDAP and Kerberos?
ACNAME
BSRV
CPTR
✅ B. SRV (Service) records specify the location of services including LDAP (_ldap._tcp) and Kerberos (_kerberos._tcp). AD is entirely dependent on these records to function.
12. What is the key difference between a recursive and an iterative DNS query?
AA recursive query is used only for reverse lookups; iterative is only for forward lookups
BIn a recursive query the resolver returns a final answer; in an iterative query, each server only refers the client to another server
CRecursive queries always use UDP, iterative queries always use TCP
✅ B. Recursive: your DNS server does all the work and returns the final answer. Iterative: each server just refers to the next one ("I don't know — try server X"). Client ↔ resolver is recursive; resolver ↔ root/TLD/auth is iterative.
13. Why is the _msdcs subdomain created separately from the main domain DNS zone?
ATo store user mailbox records separately from computer records
BTo allow independent replication and delegation of AD-specific service location records
CBecause Windows requires all DNS zones to have at least two sub-zones
✅ B. _msdcs is kept separate so it can be independently replicated to all DNS servers in the forest and delegated without affecting the main domain zone. It holds DC locators, GC locators, and PDC Emulator records.
📝 PKI / Certificate Services
14. What distinguishes a Stand-alone CA from an Enterprise CA?
AA Stand-alone CA supports GPO autoenrollment, while an Enterprise CA does not
BAn Enterprise CA requires AD and supports certificate templates and GPO autoenrollment; a Stand-alone CA does not
CThere is no functional difference; the names refer only to licensing
✅ B. Enterprise CA requires Active Directory and adds certificate templates, GPO autoenrollment, and automatic publishing to AD/LDAP. Stand-alone CA is independent of AD — best suited as an offline Root CA.
15. What is the purpose of the "IP Security IKE Intermediate" Extended Key Usage on a certificate?
AIt is required for any certificate used with EFS file encryption
BIt is required on machine certificates for IKEv2-based IPSec authentication to succeed
CIt allows a certificate to be used for SSH key-based authentication
✅ B. IKEv2-based IPSec machine auth requires the EKU "IP Security IKE Intermediate" (OID 1.3.6.1.5.5.8.2.2). Standard Computer templates do NOT include this — IKE negotiation silently fails with no log entry if missing.
16. A CRL Distribution Point (CDP) is used by clients to:
ADownload the issuing CA's certificate to build a trust chain
BDownload the Certificate Revocation List to check if a certificate has been revoked
CRequest a brand-new certificate from the CA automatically
✅ B. CDP = CRL Distribution Point = where you download the CRL. AIA (Authority Information Access) is where you download the issuing CA cert to build the trust chain. These two are commonly confused.
📝 Firewall, IPSec & OpenSSH
17. On Windows Server 2025, where must the public key be placed for a user who is a member of the local Administrators group to log in via SSH key authentication?
AC:\Users\<username>\.ssh\authorized_keys
BC:\ProgramData\ssh\administrators_authorized_keys
CC:\Windows\System32\OpenSSH\authorized_keys
✅ B. For Administrators group members, the key MUST be in C:\ProgramData\ssh\administrators_authorized_keys (not their profile folder). This file also requires strict ACLs — too-broad permissions cause sshd to silently ignore it.
18. In a Windows Firewall Connection Security Rule, what happens if one host requires IPSec authentication ("Require") but the peer host has no matching rule configured at all?
ATraffic falls back to unprotected communication automatically
BCommunication fails, since the requiring host refuses unprotected traffic
CThe connection is allowed once, then blocked on subsequent attempts
✅ B. "Require Authentication" refuses unprotected traffic entirely — no fallback. If the peer has no matching rule, the requiring side will refuse the unprotected connection and communication fails completely.
19. Which Windows network profile is automatically applied when a domain controller is reachable, and cannot be set manually by an administrator?
APrivate
BPublic
CDomain
✅ C. The Domain profile is automatically applied when a DC is reachable and cannot be manually configured. Private can be set manually; Public is the default for unidentified networks.
20. What happens when permission inheritance is disabled on a folder that previously inherited permissions?
AAll access to the folder is immediately revoked for everyone
BThe previously inherited permissions can be either deleted or copied and converted into direct permissions
CInheritance cannot be disabled once it has been applied
✅ B. When you disable inheritance, Windows prompts you to either delete the inherited entries or convert them into explicit direct permissions. Inheritance can always be disabled at any time.
