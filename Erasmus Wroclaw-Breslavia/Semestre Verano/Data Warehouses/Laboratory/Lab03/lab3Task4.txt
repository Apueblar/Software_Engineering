--------------------------------------------------------------------------------
KEY ISSUES (order by severity):
--------------------------------------------------------------------------------

1. [EXTREME] postCode (Rating) – Completely uninformative. 1 223 of 1 249
   records contain the placeholder value 0, and 26 records are NULL. No
   actual postal code data is present. This field must be excluded from all
   analyses.

2. [HIGH] date (Rating) – Mixed date formats. Approximately half the records
   use a MM/DD/YYYY string and the other half use an Excel serial date integer.
   This makes direct time-series analysis impossible without prior
   normalisation. Both formats must be converted to a unified date type
   (e.g. ISO 8601: YYYY-MM-DD).

3. [HIGH] gender (Rating) – Multiple inconsistencies: case variants
   (Male/male, Female/female), numeric placeholders for unknown (0, 1), and
   additional non-binary categories. Requires a standardisation mapping:
   lowercase normalisation, replacement of 0/1 with NULL or "Unknown", and
   decision on whether to group non-binary categories.

4. [HIGH] didPurchase (Rating) – Boolean field stoR as mixed types: the
   string "TRUE" (391 records) vs. the string "0" (858 records). "FALSE" or
   "1" never appear. Must be normalised to a consistent 0/1 or TRUE/FALSE
   encoding.

5. [MEDIUM] job (Rating) – 97 records (7.8%) use the string "0" as a
   placeholder for a missing job title instead of NULL. These must be
   converted to NULL before the field can be used as a categorical dimension.

6. [MEDIUM] city (IPlocation) – Contains spelling errors in city names
   (e.g. "Washingtn", "Dalas"). The exact count of affected records requires
   validation against a reference list of city names. Cross-referencing with
   countrycode or a geolocation API is recommended.

7. [MEDIUM] country (IPlocation) – At least one confirmed typo: "United Stats"
   instead of "United States". Recommend using 'countrycode' as the primary
   grouping attribute for country-level analysis until the country name field
   is fully validated and corrected.

8. [LOW] ratingProduct (Rating) – Floating-point precision artefacts
   (e.g. 7.5999999 instead of 7.6). Requires rounding to one decimal place
   before display or aggregation.

9. [LOW] ratingOverall (Rating) – Appears to be a derived field (average of
   the three sub-ratings). If it is recomputed in PBI measures, storing it
   in the source creates a risk of inconsistency. Recommend verifying whether
   to use the stoR value or recalculate it.

10. [LOW] isUsefull (Rating) – Attribute name contains a spelling error
    ("Usefull" instead of "Useful"). Additionally, its semantics are unclear:
    it behaves as a count (range 0–30+) but the name suggests a boolean flag.
    Domain clarification needed; rename in the data model.

--------------------------------------------------------------------------------
ADDITIONAL NOTE – JOIN COVERAGE:
  The ip field in Rating has 571 distinct values; the IPlocation table covers
  only 500 unique IPs. This means approximately 71 IPs from Rating (~12% of
  distinct IPs, affecting an unknown number of records) will produce NULL
  location data on a LEFT JOIN. Geographic analysis will therefore be
  incomplete and any aggregations by city/country will undercount.
  Severity: MEDIUM.
